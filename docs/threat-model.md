# Threat model

## Scope and assets

This model covers this repository's plugin bundles, generated tools and hooks, private result stores and CI workflows. Assets include host files and credentials, private test and browser inputs, stored evidence, and the integrity of shipped bundles. Vulnerability reporting and upstream exclusions remain in the [security policy](../SECURITY.md); contributor obligations remain in the [repository rules](agent-rules.md).

The model describes implemented boundaries, not permission to execute a tool, install a bundle or change a remote service. Generated surfaces must be reviewed together with their `lib/` and `src/` sources and manifest; the [contribution guide](../CONTRIBUTING.md#build-and-test-chain) describes the drift checks.

## Trust boundaries

| Boundary and threat | Implemented control | Limit |
| --- | --- | --- |
| Untrusted result metadata or planted filesystem entries could disclose data or redirect private writes. | The [shared result store](../shared/lib/results.ts) projects allowlisted metadata, checks directory and file identity, refuses symlinks and unsafe ownership or modes, and requires private files to be single-link regular files. See the [store contract](private-results.md) for inventory, locking and capacity. | Private storage does not isolate a compromised host or malicious process running as the same user. Do not treat a failed write as persisted evidence. |
| A selected test can run arbitrary code with the host user's authority. | The [test runner](../verification-receipts/lib/runner.ts) validates repository-relative file paths, rejects symlink paths, limits execution time and output, and forwards only `LANG`, `TZ` and absolute `PATH` entries, plus `HOME` when explicitly admitted. | This is not a sandbox. Tests can read accessible files, use binaries on `PATH` and reach the network; inspect their effects before authorizing execution. |
| A browser scenario could operate on an unintended service, control or tab. | [Scenario validation](../ui-regression/lib/scenario.ts) requires an explicit loopback origin and restricted actions. The [Aside runner](../ui-regression/lib/aside.ts) pins the local host, owns a new tab, checks origin and target uniqueness/visibility, restricts controls, and attempts to close its tab. | Loopback handlers can still mutate real resources or make outbound requests. Aside networking and transcript retention are outside this repository's control; inspect handlers and use non-sensitive inputs. |
| Caller-authored assessment context could leak sensitive material; a provider response could be malformed or overtrusted. | The [verification assessment](../verification-receipts/lib/decision.ts) validates bounded context and observed facts, uses a fixed endpoint with redirects rejected, bounds responses and validates typed answers. The [decision contract](../shared/lib/decision-contract.ts) records provider boundaries. | Screening is finite, not a privacy guarantee. This assessment sends selected context and host facts externally; model advice and confidence are not correctness proof or execution approval. Other tools have their own documented outbound payloads. |
| Untrusted pull-request code could gain runner credentials or publish misleading validation. | The [owner-dispatched workflow](../.github/workflows/pr-validate.yml) binds execution to a reviewed head SHA, runs candidate code on a disposable GitHub-hosted runner without repository secrets or persisted checkout credentials, and uses a separate trusted verifier to recheck identity and post the receipt. The [policy checker](../scripts/check-pr-policy.mjs) enforces the workflow contract. | Owner dispatch is a trust decision. A receipt applies only to its reviewed SHA; it does not authorize merging, deployment or changing repository settings. |

## Evidence and review limits

- Review changes to input projection, subprocess environments, paths, locks, permissions, provider requests and workflow permissions at their actual consumer. Do not infer safety from a tool description alone.
- A stored receipt records an observation. The [verification receipt contract](../verification-receipts/README.md) and [UI regression contract](../ui-regression/README.md) distinguish source freshness from current browser state and deployed-build binding; historical evidence does not reobserve either.
- The [store tests](../shared/tests/results.test.ts), [runner tests](../verification-receipts/tests/runner.test.ts), [assessment tests](../verification-receipts/tests/decision.test.ts), [scenario tests](../ui-regression/tests/scenario.test.ts) and [workflow fixtures](../scripts/tests/checks.test.mjs) are regression entry points, not a claim that every attack is covered.
- The [documentation checker](../scripts/check-doc-links.mjs) checks relative link targets in tracked Markdown. It does not validate this model's semantics, external services, fragment anchors or native loading of review instructions.
